# Polaris v1.0 Punch List

Status date: 2026-07-30

Current v1.0 completion estimate: 86-89%. Security, tenant isolation, database lifecycle, persistent deployment hardening, and the QuickBooks production adapter implementation are merged. Remaining production readiness is concentrated in production authentication bootstrap, QuickBooks live operator verification, Motive, external identity, and final operational controls.

## Phase 1: Security Gate

Status: Complete and merged.

Scope completed:

- route-security inventory;
- backend authentication and permission enforcement;
- organization-context validation;
- production local-auth secret hardening;
- QuickBooks OAuth state binding;
- frontend session handling;
- backend and frontend security tests.

## Phase 1.1: Tenant Isolation Hardening

Status: Complete and merged.

Scope completed:

- tenant ownership inventory;
- `organization_id` ownership for tenant-owned SQLAlchemy models;
- principal-derived query filters for tenant-owned reads and writes;
- QuickBooks credential, OAuth, sync, status, and financial cache ownership by organization ID;
- atomic QuickBooks OAuth state consumption;
- split read/write permissions for executive, connector, financial, identity, and organization operations;
- platform administrator behavior for all-organization administration;
- cross-organization negative tests.

## Phase 1.2: Integration Verification

Status: Complete and merged.

Scope completed:

- combined Security Gate and Tenant Isolation workflow verification;
- compatibility verification between merged Phase 1 changes;
- green required checks on the integrated codebase.

## Phase 2: Database Gate

Status: Complete, merged, and deployed.

Scope completed:

- database audit and table inventory;
- Alembic foundation and migration environment;
- clean SQLite and PostgreSQL-compatible installs;
- existing database adoption validation;
- tenant ownership backfill with fail-closed ambiguous cases;
- staging/production startup refusal when database is unversioned or stale;
- migration lifecycle tests and Database Gate CI;
- backup, rollback, and recovery documentation.

## Phase 2.1: Persistent Deployment Hardening

Status: Complete and merged.

Scope completed:

- Render startup runs `python -m alembic upgrade head` before Uvicorn;
- hosted staging and production are documented to use persistent PostgreSQL, not `/tmp` SQLite;
- deployed `POLARIS_FRONTEND_URL` is required outside local development;
- public `/` and `/health` responses are generic status only;
- detailed system metadata requires authentication and organization context;
- no-organization legacy tenant backfill requires explicit one-time bootstrap variables and verified ownership;
- Render deployment was restored live after the tenant backfill recovery fix.

## Phase 3A: QuickBooks Production Adapter and Read-Only Verification

Status: Complete and merged; live operator verification remains blocked until production authentication is operational.

Scope completed:

- QuickBooks production implementation audit;
- Python-owned production runtime for OAuth, encrypted credentials, refresh-token rotation, live Intuit HTTPS calls, sync, verification, and API exposure;
- Hermes retained as connector/evidence/checkpoint contract and mocked/sandbox test harness;
- company identity verification for `MOR LOGISTICS MANITOBA LIMITED`;
- paginated read-only resource reads;
- required financial report reads;
- full and incremental read-only sync into Polaris financial cache;
- safe verification endpoint and connector health states;
- minimal authenticated frontend controls for connect, verify, sync, disconnect, and reauthorization state;
- QuickBooks-specific CI and production smoke-test runbook.

## Phase 3B: Production Authentication Bootstrap

Status: Draft implementation on `phase3b/production-auth-bootstrap`.

Scope:

- keep `/api/v1/auth/local/token` disabled in production/staging;
- add one-time Mor Logistics first-admin bootstrap using Render-managed admin email and bootstrap secret;
- create `org-mor-logistics` and `mor-admin` owner identity idempotently without guessing tenant ownership;
- add bcrypt password credentials, signed short-lived access tokens, hashed refresh-token sessions, refresh rotation, logout revocation, and login rate limiting;
- update deployed frontend login from Identity/Organization IDs to email/password with bootstrap form only while available;
- add Alembic migration for auth tables and membership ID compatibility;
- document Render variables and operator bootstrap runbook.

Completion criteria:

- backend production auth tests pass;
- frontend auth tests/build pass;
- Security Gate remains green;
- Database Gate remains green;
- Runtime Verification remains green;
- Render variables are configured;
- first-admin bootstrap succeeds once;
- `POLARIS_BOOTSTRAP_SECRET` is removed after success;
- deployed frontend login succeeds;
- `/api/v1/auth/me` confirms `mor-admin` owner permissions.

## Later Phases

The following phases are intentionally out of scope for Phase 3B:

1. Motive production adapter / Issue #62.
2. Outlook production adapter.
3. API-001 response/versioning migration.
4. QuickBooks accounting writes.
5. Broad CI/CD hardening unrelated to auth verification.
6. External production identity provider.

Do not mark Polaris v1.0 production-ready until every phase has passing automated evidence, production operator evidence where required, and human approval.
