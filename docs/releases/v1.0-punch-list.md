# Polaris v1.0 Punch List

Status date: 2026-07-30

Current v1.0 completion estimate: 84-88%. Security, tenant isolation, database lifecycle, and persistent deployment hardening are merged. Remaining production readiness is concentrated in QuickBooks live operator verification, Motive, external identity, and final operational controls.

## Phase 1: Security Gate

Status: Complete and merged.

Scope completed:

- route-security inventory;
- backend authentication and permission enforcement;
- organization-context validation;
- production local-auth secret hardening;
- QuickBooks OAuth state binding;
- frontend session handling;
- backend and frontend security tests.

## Phase 1.1: Tenant Isolation Hardening

Status: Complete and merged.

Scope completed:

- tenant ownership inventory;
- `organization_id` ownership for tenant-owned SQLAlchemy models;
- principal-derived query filters for tenant-owned reads and writes;
- QuickBooks credential, OAuth, sync, status, and financial cache ownership by organization ID;
- atomic QuickBooks OAuth state consumption;
- split read/write permissions for executive, connector, financial, identity, and organization operations;
- platform administrator behavior for all-organization administration;
- cross-organization negative tests.

## Phase 1.2: Integration Verification

Status: Complete and merged.

Scope completed:

- combined Security Gate and Tenant Isolation workflow verification;
- compatibility verification between merged Phase 1 changes;
- green required checks on the integrated codebase.

## Phase 2: Database Gate

Status: Complete, merged, and deployed.

Scope completed:

- database audit and table inventory;
- Alembic foundation and migration environment;
- clean SQLite and PostgreSQL-compatible installs;
- existing database adoption validation;
- tenant ownership backfill with fail-closed ambiguous cases;
- staging/production startup refusal when database is unversioned or stale;
- migration lifecycle tests and Database Gate CI;
- backup, rollback, and recovery documentation.

## Phase 2.1: Persistent Deployment Hardening

Status: Complete and merged.

Scope completed:

- Render startup runs `python -m alembic upgrade head` before Uvicorn;
- hosted staging and production are documented to use persistent PostgreSQL, not `/tmp` SQLite;
- deployed `POLARIS_FRONTEND_URL` is required outside local development;
- public `/` and `/health` responses are generic status only;
- detailed system metadata requires authentication and organization context;
- no-organization legacy tenant backfill requires explicit one-time bootstrap variables and verified ownership;
- Render deployment was restored live after the tenant backfill recovery fix.
