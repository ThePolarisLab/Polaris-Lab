# Polaris v1.0 Punch List

Status date: 2026-07-30

Current v1.0 completion estimate: 82-86%. The code foundation is strong, but live production readiness still depends on persistent database cutover, QuickBooks production verification, Motive, external identity, and final operational controls.

## Phase 1: Security Gate

Status: Complete and merged.

Scope completed:

- route-security inventory;
- backend authentication and permission enforcement;
- organization-context validation;
- production local-auth secret hardening;
- QuickBooks OAuth state binding;
- frontend session handling;
- backend and frontend security tests.

## Phase 1.1: Tenant Isolation Hardening

Status: Complete and merged.

Scope completed:

- tenant ownership inventory;
- `organization_id` ownership for tenant-owned SQLAlchemy models;
- principal-derived query filters for tenant-owned reads and writes;
- QuickBooks credential, OAuth, sync, status, and financial cache ownership by organization ID;
- atomic QuickBooks OAuth state consumption;
- split read/write permissions for executive, connector, financial, identity, and organization operations;
- platform administrator behavior for all-organization administration;
- cross-organization negative tests.

## Phase 1.2: Integration Verification

Status: Complete and merged.

Scope completed:

- combined Security Gate and Tenant Isolation workflow verification;
- compatibility verification between merged Phase 1 changes;
- green required checks on the integrated codebase.

## Phase 2: Database Gate

Status: Complete, merged, and deployed.

Scope completed:

- database audit and table inventory;
- Alembic foundation and migration environment;
- clean-install migration path;
- safe existing database adoption validation;
- deterministic tenant backfill for single-organization legacy data;
- fail-closed multi-organization and no-organization legacy behavior;
- staging/production startup refusal when database is unversioned or stale;
- migration lifecycle tests and Database Gate CI;
- backup, rollback, and recovery documentation.

## Phase 2.1: Persistent Deployment Hardening

Status: In progress on `phase2.1/persistent-deployment-hardening`.

Scope:

- require Render startup to run `python -m alembic upgrade head` before Uvicorn;
- document that hosted staging and production must use persistent PostgreSQL, not `/tmp` SQLite;
- require deployed `POLARIS_FRONTEND_URL` outside local development;
- reduce public `/` and `/health` responses to generic status only;
- require authentication and organization context for detailed system metadata;
- preserve local/test SQLite support;
- verify Security Gate, Database Gate, backend tests, frontend tests/build, root TypeScript tests, and runtime verification remain green.

Completion criteria:

- Draft PR reviewed and CI green;
- Render `DATABASE_URL` switched to persistent PostgreSQL by the operator;
- PostgreSQL database migrated to Alembic head;
- `/health` returns 200 after deploy, redeploy, and free-tier wake-up;
- tenant data and connector credentials persist across restart/redeploy;
- live QuickBooks verification remains blocked until these checks pass.

## Phase 3A: QuickBooks Production Adapter and Read-Only Verification

Status: Blocked until Phase 2.1 persistent database cutover is complete.

Scope boundary:

- no live OAuth, refresh-token verification, read-only financial sync, or Issue #61 production checklist item should be marked complete while Render uses temporary SQLite storage.

## Later Phases

The following phases remain intentionally out of scope for Phase 2.1:

1. Motive production adapter.
2. Outlook production adapter.
3. API-001 response/versioning migration.
4. Broad deployment infrastructure beyond Render migration/start documentation.
5. QuickBooks production adapter implementation or live verification.
6. External production identity provider.

Do not mark Polaris v1.0 production-ready until every phase has passing automated evidence, persistent production storage, live integration evidence, and human approval.
