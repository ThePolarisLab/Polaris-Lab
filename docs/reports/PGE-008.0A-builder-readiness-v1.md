## Runtime commands

### Backend

```bash
cd chief-of-staff/backend
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Verify:

```bash
curl http://127.0.0.1:8000/health
```

### Frontend

```bash
cd chief-of-staff/frontend
npm ci
npm test
npm run build
npm run dev
```

## Builder environment architecture

| Environment | Purpose | Data profile | Allowed operation mode |
|---|---|---|---|
| Development | Local engineering and test | Synthetic/local | Engineering actions only |
| Staging | Integration and release verification | Sanitized or test tenant | Observer/advisory |
| Mor Logistics Builder | Controlled founding-builder validation | Approved Mor Logistics sources | Observer/advisory by default |

Runtime identity is supplied through environment configuration. No environment requires source-code edits.

## Go/no-go assessment

### GO

- Controlled local development.
- CI-based backend and frontend verification.
- Runtime health monitoring without exposing secrets.
- Environment-driven Executive and Builder workspaces.
- Controlled Mor Logistics observer/advisory evaluation.
- Continued development of Mission 003 on the verified platform baseline.

### NOT YET GO

- Unsupervised production automation.
- External-system mutations without dedicated approval controls.
- General multi-tenant public release.
- Production authentication/authorization rollout.

These restrictions are intentional governance boundaries and do not block completion of the Builder Platform Baseline.
