## Engineering Decisions

The Fleet V1 foundation reuses the canonical Python/FastAPI runtime and existing Motive persistence. It exposes read-only organization-scoped readiness/contract information rather than introducing parallel persistence or a new sync engine.

Vehicle contract certification treats provider vehicle ID, number, VIN, make, model, year, license plate, and provider status as confirmed provider fields. MOR business-active state, vehicle-driver association, location, odometer, engine hours, utilization, IFTA, exceptions, and Fleet attention remain deferred.

The `/v1/users` contract certification similarly separates confirmed provider fields from derived/deferred semantics. No PII, provider IDs, raw payloads, credentials, headers, or secrets are exposed by certification endpoints.

PR #151 certifies a narrow provider-role classifier from `provider_payload_metadata.role`: `driver` → Motive driver role; `fleet_user` or `admin` → non-driver provider role; missing, blank, non-string, or undocumented values → unknown role. This is computed read-only from existing organization-scoped records and requires no migration. Critically, `role=driver` plus provider `status=active` does not mean MOR active driver.

## Research / Verification Notes

The ACE missed schedule on August 14 was isolated to the single scheduled GitHub trigger because manual workflow dispatch succeeded and the new Outlook ACE report imported correctly. Motive certification work continues to use explicit confirmed/derived/deferred classifications. The provider-role work recognizes only documented/observed literals and deliberately classifies undocumented roles as unknown rather than guessing.
