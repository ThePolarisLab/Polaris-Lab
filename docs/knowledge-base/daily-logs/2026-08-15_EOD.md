## Official Decisions

- Provider-schema compatibility and persistence readiness remain separate decisions.
- Motive `GET /v1/vehicle_utilization` uses the documented `vehicle_idle_rollups -> vehicle_idle_rollup` envelope and `vehicle.id` identity; request-window context is not treated as a provider-returned reporting period.
- Missing provider rollups do not create synthetic zero metrics, inactive/no-activity state, or durable rows.
- Unknown provider vehicles fail closed and are not auto-created; duplicate returned rollups also fail closed.
- Future durable writer requests use a Polaris-owned canonical metric policy: `metric_units=true`, `X-Metric-Units: true`, canonical unit system `metric`, with unit conversion disabled.
- The Polaris replay identity `organization_id + motive_vehicle_id + request_window_start + request_window_end` is certified under that fixed unit-policy precondition. It is not claimed to be a Motive provider natural key.

## Engineering Decisions

The semantics layer records the Motive v1 utilization request filters, documented response envelope, vehicle identity, utilization percentage, idle/driving time in seconds, idle/driving fuel meanings, metric-unit indicator, and company-configured rollup-timezone behavior. The exact MOR company rollup timezone remains unresolved.

A manual bounded evidence route was introduced with strict limits: at most three stored organization-owned vehicles and exactly three provider requests over day A, day B, and the combined window. It compares only additive metrics and does not persist results, advance checkpoints, schedule work, or activate UI/business behavior.

The authorized bounded production observation selected three vehicles. One rollup was returned in each tested window; two selected vehicles were absent; no duplicate or unexpected vehicles were observed; pagination total matched the returned count; and truncation was not observed. For the returned vehicle, the four additive metrics matched across the two single days and combined window with consistent unit context. This observation is intentionally not promoted to a universal Motive guarantee.

The durable writer contract now requires returned validated rollups only. Provider absence produces `provider_rollup_absent`; unknown vehicles and duplicate rows fail closed. Request window and provider reporting period remain separate. Checkpoints and scheduled ingestion remain disabled.

The canonical future writer unit policy is code-controlled and fixed to metric. Explicit unit controls accept exact Python booleans only; invalid runtime values fail before a provider request. Environment configuration remains a verifier/evidence boundary rather than authority for the future durable writer.

## Research / Verification Notes

The bounded evidence work supports the current request-window replay identity under a fixed canonical unit policy, but it does not establish a Motive provider natural key or universal cardinality/no-activity behavior.

Official provider semantics indicate that utilization rollups use the Motive company-configured rollup timezone rather than `X-Time-Zone`. The exact MOR company setting still must be established before scheduled daily ingestion can be certified.
