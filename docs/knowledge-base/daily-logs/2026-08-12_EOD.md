- Treat the production-observed `vehicle_idle_rollups` / `vehicle_idle_rollup` shape as the supported parser input for this stage.
- Keep request start/end dates as request context only; do not claim that they are provider reporting-period fields until Motive semantics are authoritatively established.
- Unknown provider vehicle identities produce a typed `unknown_vehicle` outcome and must not auto-create vehicles.
- Vehicle association is organization-scoped and read-only.
- Continue the no-persistence boundary for vehicle utilization until storage semantics, idempotency, units, period identity, checkpoint behavior, and KPI interpretation are separately certified.
- Provider-sensitive values and raw payloads must not enter routine logs or source metadata.

## Principles Reaffirmed

- Evidence before inference.
- Deterministic normalization before persistence or automation.
- Explicit certification boundaries: an observed schema does not certify business semantics.
- Organization isolation for provider-to-local identity association.
- Unknown external identities fail safely rather than mutating local master data.
- Privacy-safe observability: schema/outcome metadata is preferred over provider identifiers, VINs, vehicle numbers, metric values, headers, secrets, or raw payloads.
- Incremental rollout: parser and association may ship independently of persistence, scheduling, KPIs, and frontend activation.

## Engineering Decisions

PR #138 introduced a side-effect-constrained parser module with an explicit parser version (`motive_vehicle_idle_rollup_v1`). Numeric metrics are normalized using `Decimal`, avoiding premature float-based business semantics.

The parser requires the observed container and wrapper structure and returns safe typed parse failures when the envelope, wrapper, vehicle identity, or metric types are invalid. Request dates can be carried into the normalized record but remain explicitly contextual.

Association uses existing `MotiveVehicleRecord` rows filtered by both organization and provider vehicle ID. A match returns the existing local record identity; an unknown provider vehicle returns `unknown_vehicle` without inserting or updating vehicle master data.

Logging remains outcome-oriented. Source-key capture filters sensitive key names, and routine logs do not include provider IDs, VINs, vehicle/unit numbers, metric values, raw payloads, headers, API keys, tokens, or secrets.

## Research / Contract Notes

The production-observed response provides sufficient evidence to build a bounded parser, but it does not resolve all business semantics. In particular, request start/end dates remain request context because the observed rollup does not establish authoritative reporting-period start/end fields.

The observed metrics can therefore be normalized without yet deciding durable storage keys, reporting-period identity, KPI formulas, aggregation behavior, or checkpoint advancement rules. This separation reduces the risk of encoding unsupported assumptions into persistent data.
