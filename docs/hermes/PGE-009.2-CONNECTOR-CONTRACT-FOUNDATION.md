# PGE-009.2 — Connector Contract Foundation

## Status

Implemented in PR #52; pending human review and CI.

## Executive value

This increment gives Polaris one governed, provider-neutral boundary for every future enterprise integration. Microsoft 365, Motive, QuickBooks Online, TMS, fuel, maintenance, and future adapters can now share the same tenant, provenance, lifecycle, health, synchronization, and authentication semantics.

## Included

- immutable connector identity, scope, capability, and synchronization contracts;
- required organization and tenant scope;
- credential references without raw secret values;
- full and incremental synchronization modes;
- checkpoint, partial-failure, and retryability result fields;
- evidence envelopes with source provenance, timestamps, schema version, correlation, and idempotency;
- authentication-provider contracts for OAuth 2.0, API keys, client credentials, and service accounts;
- health and readiness reporting;
- guarded connector lifecycle base class;
- contract validation and deterministic tests;
- public exports from `src/hermes/connectors`.

## Explicit exclusions

This increment does not include:

- a live vendor integration;
- connector registration or scheduling;
- retry or circuit-breaker implementation;
- secret storage;
- persistence or normalization;
- autonomous email, accounting, dispatch, payment, or other material actions.

Those capabilities remain assigned to later Hermes milestones.

## Lifecycle

```text
Ready
  -> Authenticating
  -> Connected
  -> Synchronizing
  -> Connected or Degraded
  -> Disconnected

Any unhandled connector failure moves the connector to Failed.
```

Cross-tenant operations and invalid state transitions fail closed through structured `ConnectorContractError` codes.

## Security and trust boundaries

- Every connector and request carries explicit organization and tenant scope.
- Credential data is represented only by a secure reference.
- Raw vendor SDK objects are absent from the domain contract.
- Every evidence item requires source identity, source record identity, observation time, ingestion time, schema version, correlation ID, and idempotency key.
- Material write actions are not authorized by this contract foundation.

## Verification

Automated tests verify:

- descriptor requirements;
- evidence and idempotency requirements;
- lifecycle enforcement;
- synchronization and checkpoint behavior;
- health reporting;
- rejection of cross-tenant requests.
