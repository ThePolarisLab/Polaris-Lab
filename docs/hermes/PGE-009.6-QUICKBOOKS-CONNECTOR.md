# PGE-009.6 — QuickBooks Connector

## Status

Implemented for Hermes runtime integration.

## Purpose

The QuickBooks connector supplies Polaris with normalized, evidence-backed financial records while preserving vendor isolation. Athena and future executive read models consume Hermes evidence rather than QuickBooks-specific objects.

## Capabilities

- credential-reference authentication boundary
- full synchronization
- incremental synchronization
- runtime checkpointing
- health reporting
- deterministic evidence envelopes
- configurable resource and report selection

## Resources

The connector can synchronize company, customers, vendors, accounts, invoices, payments, bills, purchases, and journal entries.

## Reports

The connector supports Profit and Loss, Balance Sheet, Cash Flow, aged receivables, and aged payables report evidence.

## Checkpoint Model

The checkpoint stores the most recent observed update timestamp and any incomplete per-resource cursor state. Hermes persists this checkpoint and supplies it to the next incremental synchronization.

Schema version: `quickbooks-checkpoint-v1`.

## Evidence

Each imported item includes organization and tenant scope, connector identity, source record identity, observation and ingestion times, correlation ID, schema version, and an idempotency key.

Schema version: `quickbooks-evidence-v1`.

## Production Adapter Boundary

`QuickBooksApiClient` intentionally defines the transport and OAuth boundary without embedding HTTP or secret-storage policy into the connector. A production adapter must implement token acquisition and refresh, QuickBooks Online queries and reports, pagination, rate-limit handling, and safe disconnect behavior.
