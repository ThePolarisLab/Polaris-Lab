# PGE-009.6 — QuickBooks Connector

## Status

Implemented for Hermes runtime integration. Production QuickBooks Online access for Polaris Phase 3A is owned by Python FastAPI; Hermes remains the connector/evidence/checkpoint contract and mocked/sandbox test harness.

## Purpose

The QuickBooks connector supplies Polaris with normalized, evidence-backed financial records while preserving vendor isolation. Athena and future executive read models consume evidence rather than QuickBooks-specific credential objects.

## Capabilities

- credential-reference authentication boundary for Hermes tests/sandbox adapters
- full synchronization contract
- incremental synchronization contract
- runtime checkpointing
- health reporting
- deterministic evidence envelopes
- configurable resource and report selection

## Resources

The connector can represent company, customers, vendors, accounts, invoices, payments, bills, purchases, and journal entries.

## Reports

The connector supports Profit and Loss, Balance Sheet, Cash Flow, aged receivables, and aged payables report evidence.

## Checkpoint Model

The checkpoint stores the most recent observed update timestamp and any incomplete per-resource cursor state. Hermes persists this checkpoint and supplies it to the next incremental synchronization.

Schema version: `quickbooks-checkpoint-v1`.

## Evidence

Each imported item includes organization and tenant scope, connector identity, source record identity, observation and ingestion times, correlation ID, schema version, and an idempotency key.

Schema version: `quickbooks-evidence-v1`.

## Production Adapter Boundary

ADR-026 makes Python FastAPI the authoritative production runtime for QuickBooks OAuth, encrypted credentials, refresh-token rotation, live Intuit HTTPS calls, tenant-owned financial cache writes, and API exposure. Hermes must not receive production refresh tokens, access tokens, client secrets, OAuth codes, raw OAuth state, encryption keys, or realm IDs in Phase 3A.

`QuickBooksApiClient` remains useful for contract tests, sandbox experiments, and future sanitized Polaris evidence consumers. Any future direct Hermes production access requires a new ADR and must not duplicate Python token rotation.
